# 2026-10-26 - Renovate

Renovate runs from `case/homelab` (`infra/renovate/config.js` lists this repo), on the fleet's Friday schedule. Planned and reviewed with codex and agy.

## Decisions

- **One owner per shared version.** caddy, node and uv are pinned in both the `Dockerfile` and `mise.toml`; pnpm in both `web/package.json` and `mise.toml`. The `Dockerfile` and `package.json` own them, and Renovate is disabled for the `mise.toml` copies. `bin/renovate-postupgrade` copies the owners' versions over after every update, and `bin/lint` runs it with `--check`. Rejected: grouping the two copies into one PR. Their datasources (Docker Hub tags, GitHub releases) carry different release timestamps, so the 14-day wait can release one and hold the other.
- **`uv_build` follows uv.** The hook sets `[build-system].requires` to `uv_build>=X.Y.Z,<X.(Y+1).0` from the Dockerfile's uv, and Renovate's own `build-system.requires` updates are disabled.
- **The hook recomputes jar hashes.** Renovate bumps the path in `tools/ics-validate.lock` (regex manager, `maven` datasource) and leaves the old hash. The hook downloads each path that HEAD's lock does not have, checks it against Maven Central's `.sha1`, and writes the SHA-256. A path HEAD already has must keep HEAD's hash. Rejected: homelab's manual-hash pattern, under which every jar PR arrives red.
- **The hook parses Dockerfile FROM lines with a strict pattern.** No conforming Dockerfile parser runs in the Renovate image. Every FROM must be `FROM <image>:<tag>@sha256:<digest>[ AS <name>]`, so anything else fails closed.
- **It runs on Python 3.12**, the Renovate image's (`renovate/renovate:44.149.2`). It uses the standard library only, ruff targets py312 for it, and `bin/test` runs its tests on 3.12 as well as 3.14. That is also why it keeps its own copy of `fetch.py`'s HTTPS-only redirect guard: the package needs 3.14 and is not installed in the Renovate image.
- **The 14-day wait also binds the resolvers.** Renovate runs `uv lock --upgrade-package <name>` without a version (`lib/modules/manager/pep621/processors/uv.ts`), so uv could pick a newer release or transitive dep than Renovate checked. `[tool.uv] exclude-newer = "14 days"` (stored as `exclude-newer-span = "P14D"` in `uv.lock`, so no churn) and pnpm's `minimumReleaseAge: 20160` close that. Cost: a security fix younger than 14 days needs a hand exemption (`exclude-newer-package`, `minimumReleaseAgeExclude`). Chosen by the owner.
- **`ghcr.io/astral-sh/uv` is `timestamp-optional`.** Renovate's docker datasource has release timestamps only on Docker Hub, and Renovate 42+ treats a missing timestamp as too new, so uv would never update.
- **Manual moves:** Node, Java (Temurin) and Python majors, and Python minors. Python comes from Alpine's `python3~3.14`, and `javac --release` matches the Temurin major.
- **Monthly lock maintenance** (`* * 1-7 * *`), so transitive pins such as `tzdata` move. Renovate's default window (before 4am Monday) never meets the 14:30 UTC run.
- **Jars stay in one PR even for majors**, so `slf4j-api` and `slf4j-nop` move together.

## Verified

- `renovate-config-validator --strict` and a `--platform=local --dry-run=lookup` inside `renovate/renovate:44.149.2` (RE2 engine). The lookup extracted all six jars with Maven coordinates, proposed uv 0.13.6 despite GHCR's missing timestamps, and marked the mise node and pnpm copies `disabled`. Without a token, the mise caddy and uv copies show `github-token-required`, which is checked before package rules.
- Renovate 44.149.2 replaces every occurrence of the version in a regex match (`autoReplaceGlobalMatch` defaults to true), so a lock path's two copies of the version move together.
